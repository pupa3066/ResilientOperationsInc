### 🔭 Node 1 — Observation Layer (`observation/`)

**Files:**
- `observation/seed_data.py` — Real-life SRE incident data (logs, metrics, traces)
- `observation/observe.py` — Anomaly detection + signal surfacing engine

**What it does:**
- Ingests logs, metrics, and distributed traces per incident
- Applies anomaly detection rules (error rate, latency, packet loss, pool exhaustion, etc.)
- Surfaces structured signals with severity scoring
- Outputs: anomaly table, error log summary, failed trace chain
- Passes signal bundle to Reasoning Layer (Node 2)

**3 Real Incidents Loaded:**

| ID | Incident | Severity | Signals |
|---|---|---|---|
| INC-2024-0312 | AWS us-east-1 AZ-b packet loss — cascading RDS/Lambda failures | 🔴 CRITICAL | 14 |

| INC-2024-0891 | Payment service DB connection pool exhaustion — checkout failures | 🔴 CRITICAL | 11 |

**Sample output per incident:**
```
Anomaly Signals  → error rate, latency spike, packet loss, lambda failures
Error Logs       → top 4 errors with timestamp + service
Trace Chain      → full span path showing where requests died
Signal Count     → total signals → ready for Reasoning Layer
```

### 🧠 Node 2 — Reasoning Layer (`reasoning/`)

**Files:**
- `reasoning/reason.py` — Gemini-powered root cause analysis engine

**What it does:**
- Feeds observation signals (logs) into Gemini 2.0
- Builds a hypothesis tree with HIGH/MED/LOW priority per hypothesis
- Returns root cause with confidence % and evidence citations
- Maps blast radius across affected services
- Outputs structured next steps → passes to Planner (Node 3)
- Supports `MOCK_GEMINI=1` mode for demo without API quota

**Results across 3 incidents:**

| Incident | Root Cause | Confidence |
|---|---|---|
| incident-1 | DB pool exhausted — 47s long-running query blocking connections | 92% |
| incident-2 | 18% packet loss in AZ-b → RDS timeouts → Lambda failures | 89% |
| incident-3 | auth-svc Java heap exhausted (512Mi) → OOMKiller → CrashLoopBackOff | 95% |

**Run commands:**
```bash
# Live Gemini
GEMINI_API_KEY=your_key .venv/bin/python -m reasoning.reason

# Mock mode (no API key needed)
MOCK_GEMINI=1 GEMINI_API_KEY=x .venv/bin/python -m reasoning.reason
```

### 📋 Node 3 — Planner (`planner/`)

**Files:**
- `planner/plan.py` — Gemini-powered remediation plan generator

**What it does:**
- Takes Gemini root cause output and generates ordered steps
- Classifies each step as `READ_ONLY` (auto-execute) or `MUTATING` (needs approval)
- Includes estimated time and risk level (LOW/MED/HIGH) per step
- Passes plan to HITL Controller

**Per incident:** 6 steps generated, 3 require HITL approval

---

### 🔐 Node 4 — HITL Controller (`hitl/`)

**Files:**
- `hitl/controller.py` — Human-in-the-loop approval gate
- `hitl/audit_log.jsonl` — Immutable audit trail of all decisions

**What it does:**
- Auto-executes all `READ_ONLY` steps without interruption
- Gates every `MUTATING` step behind SRE approval
- Prompts: `Approve? [y/n/skip]` with action, risk, and time estimate
- Logs every decision (APPROVED / REJECTED / SKIPPED) to audit log
- Supports `AUTO_APPROVE=1` for demo mode

### 🚀 End-to-End Orchestrator (`main.py`)

Runs all 4 nodes in sequence for every incident:

```
Observation → Reasoning → Planning → HITL → ✓ RESOLVED
```
